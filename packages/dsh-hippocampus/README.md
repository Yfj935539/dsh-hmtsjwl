# 🧠 海马体记忆 Agent（Hippocampus）v5.2 —— Wazome Memory Network v5.2

[![GitHub](https://img.shields.io/badge/源码仓库-Yfj935539%2Fdsh-hmtsjwl-3d6df2?style=flat-square&logo=github)](https://github.com/Yfj935539/dsh-hmtsjwl)

DeepSeek Harness 客户端插件：为 Agent 提供**有记忆、可创造、可视化**的长期记忆系统，
基于 **Wazome Memory Network v5.2** 风格深度改写，强化**项目文件夹记忆**，
用于**项目推进**与**长上下文污染优化**。

- 在「对话 / 轨迹」之后新增 **「记忆」** 标签页（`conversation.view` 插槽，order 20）
- 记忆内容：**用户偏好喜好、交流方式、任务进行中的工作状态、洞察**等
- 每一个记忆**分支**都可以在界面中**手动编辑、修正、归档、删除**（含修正历史）
- Agent 在工作中可随时用 **memory_write / memory_read / memory_search / memory_edit /
  memory_forget / memory_stats / memory_context / memory_evolve / memory_analyze /
  memory_export / memory_import / memory_review** 按指令写入与读取
- 对话前自动注入记忆包（`systemPrompt.section`，每轮 turn 前），高质量记忆优先

## v5.5 数据驱动神经网络（当前版本）—— 交叉即新想法，权重即大小

| 机制 | 实现 |
| --- | --- |
| **连线交叉 → 真实新想法** | `segSegDist3()` 3D 线段检测：两条联想连线在概念空间交汇时，在**记忆库中真实创建**一条「⟡ 联想交汇」弱 insight 分支（记录 4 个交汇记忆的关联、KEY 去重、与 4 源节点建弱突触 0.16、强度 0.28）—— 可检索、可注入、可演化、可修剪，随检索强化慢慢变强，真正进入记忆网络 |
| **检索即思维触发** | 每次检索命中后自动检测交汇（5 分钟冷却、fire-and-forget 不阻塞）—— 检索是思维活动，交汇是思维产物 |
| **节点大小 = 真实权重** | 节点半径 = 强度 × 连接度 × 层级：中枢节点（高连接/高强/核心）显著更大，分支/弱记忆明显更小 —— 一眼分辨重要节点 |
| **节点间距优化** | 叶子在各自工作区扇区内做二次 Fibonacci 均匀散布 + 半径扩大，消除堆叠/过近 |
| **⟡ 交汇节点标识** | 画布上紫色星标标记「联想交汇」节点，点击可见 4 节点关联内容 |

## v5.4 神经网络协作（历史基线）—— 像人脑一样调用

| 机制 | 实现 |
| --- | --- |
| **激活锚点（工作记忆延续）** | `AnchorBank`：检索/读取/注入命中的记忆成为激活锚点（强度叠加、10 分钟 TTL、容量 24 自动淘汰）；检索按锚点加权（×1.25）——「接着上次想的继续想」；画布金色锚环 + 呼吸脉冲可视化工作记忆 |
| **主动记忆梳理（先检索再输出）** | 监听 `agent/inbox/inserted`：用户消息进入收件箱 → 立即异步语义检索（发生在模型输出消耗 token 之前）→ 缓存；系统提示组装时注入「与您本条消息相关的记忆」，再决定输出 |
| **上下文感知注入** | 注入 = 本条消息预检索 + 激活锚点 + 核心记忆（质量过滤）+ 最近 1h 新增，融合去重最多 14 条 |
| **归纳连线** | 写入时自动建立：同会话近 24h 时序连线（0.5）、同项目（0.3/同类 0.4）、共享 ≥2 标签（0.3）—— 网络更稠密，联想路径更多 |
| **两轮联想扩散** | 联想链：种子 → 邻居 → 邻居的邻居（×0.6 衰减），多跳联想如人脑「想起 A → 想起 B → 顺带想起 C」 |
| **相关记忆提示** | 写入时检测 0.5~0.9 语义相关的旧记忆，随结果返回（memory_write 提示「相关记忆 n 条」）—— 感知关联而非粗暴合并 |

## v4.1 项目精准度（当前版本）

海马体的本职是**决定大脑对「当前项目」的判断精准度与掌握能力**。统一记忆库让所有项目记忆同库共存（跨项目沉淀价值保留），但若不区分项目归属，当前项目的记忆会被其他项目的同类记忆稀释/越权召回，直接拉低判断准确度。v4.1 在检索、去重、演化三处统一引入「项目相关性」口径：

| 环节 | 实现 |
| --- | --- |
| **检索项目聚焦** | `projectWeight()`：命中「当前项目」的记忆检索分 ×1.3 优先召回；其他项目记忆 ×0.55 降权但**不隔离**；偏好/交流/无项目归属的全局记忆不降权。排序基于 `sameProject()`（精确匹配或互为父目录前缀，兼容多窗口同工作区） |
| **去重/合并同项目限制** | `writeBranch` 去重与 `evolve` 演化合并，仅允许【同一项目】的高相似记忆合并——防止两个不同项目里语义相近但内容独立的记忆被错误合并、丢失各自项目细节 |
| **心智模型对应** | 记忆按「项目」归档组织，但大脑在任何项目都能检索到全部沉淀；只有对**判断当前项目**真正有用的记忆被顶到最前，其余作为背景知识保留，避免噪声干扰判断 |

## v3.1 自动化机制

| 机制 | 实现 |
| --- | --- |
| **每小时轨迹喂养** | 宿主端每小时自动扫描活跃会话（48h 窗口）的轨迹（`sessionQuery.readSurface`，与「轨迹」标签页同源），读取最近事件（用户/助手/工具消息）→ 无 LLM 启发式提炼（信号句 + 高频词 + 角色时间线，长对话全量扫描、时间线保留最新）→ upsert「会话精华」分支（按小时窗口归并，自动去重/链接）；记忆页「喂养轨迹」按钮手动触发 = 全量喂养整个对话历史 |

| **超限自动优化** | ① 提炼过期记忆精华（合并进「历史记忆精华」分支）→ ② 删除过期/无效记忆（含向量与突触）→ ③ 清除孤儿向量 → ④ checkpoint + VACUUM 压缩 |

| **启动自检** | DSH 启动 5 秒后自动执行一次增量轨迹喂养 + 语义模型后台预热（启动即绑定记忆轨迹） |
| **环境变量** | `DSH_HIPPOCAMPUS_FEED_MS`（喂养间隔，默认 3600000=1h）、`DSH_HIPPOCAMPUS_SIZE_LIMIT`（库上限字节，默认 1GB）、`DSH_HIPPOCAMPUS_MAX_NODES`（节点上限，默认 1000） |

## 项目推进 & 上下文污染优化工作流

长会话中上下文过长会产生污染（冗余历史稀释注意力、陈旧信息干扰判断）。
用海马体把知识**外置**到统一记忆库（跨目录打通），按需 JIT 加载：

1. **任务开始**：`memory_context` 拉取记忆包（或 `memory_read(kind=workstate)` 看上次进度）
2. **任务推进**：阶段变化时 `memory_write(kind=workstate)` 记录任务/阶段/进度
3. **关键结论**：用 `memory_write(kind=insight)` 沉淀洞察（自动去重 + 自动标签 + 突触连接）
4. **长会话刷新**：感到上下文冗长时再次 `memory_context` 刷新锚点，而不是依赖上下文里的旧摘要
5. **定期整理**：`memory_stats` 查看健康度，`memory_evolve` 合并近重复、修剪弱连接，防止记忆库自身污染
6. **轨迹喂养**：点击记忆页「喂养轨迹」把当前对话历史提炼进记忆库；每小时自动增量喂养

## 使用

1. 打开任意会话，顶部出现 **对话 · 轨迹 · 记忆** 三个标签
2. 「记忆」页：
   - **左侧面板**：图例（种类颜色编码 + 激活强度/突触说明）+ 自学习面板（神经元/突触/适应度，动画开关）+ 自演化面板（代际/已合并/已修剪，按钮=真实演化/修剪）
   - **中央画布**：分层神经网络（按种类纵向排列），节点发光强度=激活能量，连接线=突触权重+脉冲动画；**输入搜索词驱动激活**（命中节点高亮、无关节点变暗）；单击节点=选中，拖拽=移动，双击=重置视图，右键=清除选择
   - **底部状态栏**：选中节点 ID / 种类 / 激活强度 / 连接数 / 年龄；右侧 FPS / Gen / LR / Fit 实时指标
   - **右侧列表**：每条记忆卡片（显示连接数 ⚡ 与年龄）→ **编辑**（改标题/正文/种类/标签/强度/状态）、归档/恢复、删除
   - 顶部工具栏：**项目/全局**作用域切换（显示当前项目名）、搜索框、种类筛选、**＋ 新建分支**、刷新
   - 快捷键：**空格**=停止/激活动画，**F**=演化（合并近重复），**E**=隐藏/显示弱连接
3. 让 Agent 记录：直接说「记住……」「我偏好……」，我会用 memory_write 写入；
   长任务中我会用 memory_read / memory_context 回忆，并用工作状态分支记录进度
